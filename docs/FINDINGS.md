# Security and Engineering Findings Register

This register records concrete security gaps, policy bypasses, and unimplemented controls discovered during Phase 0 baseline inspection and subsequent red-team passes.

| ID | Severity | Component | Description | Reproduction / Attack Vector | Status | Planned / Fixed Phase |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| FINDING-001 | High | `src/index.ts` | RBAC middleware (`server.use("tools/list", ...)` and `server.use("tools/call", ...)`) is not registered on the `MCPServer` instance; `rbacManager.filterTools` is never invoked at runtime | Any MCP client calling `tools/list` receives all registered tool descriptors regardless of caller credentials | OPEN | Phase 2 (P0-4) |
| FINDING-002 | High | `src/index.ts` | Resource `schema://catalog` returns the full `TABLE_METADATA` object without authentication or role filtering | Reading `schema://catalog` without credentials exposes admin-only table names (`security_incidents`, `api_keys`) and PII column metadata | OPEN | Phase 2 (P0-4) |
| FINDING-003 | High | `src/database/engine.ts` | Query timeout parameter `timeoutMs` is stored and echoed in response metadata, but synchronous `db.exec()` runs on the main Node thread with no timer or worker termination | A CPU-heavy recursive CTE blocks the Node event loop indefinitely despite the configured deadline | OPEN | Phase 2 (P0-1) |
| FINDING-004 | Medium | `src/database/engine.ts` | Response metadata reports a fixed memory cap string, but neither SQLite page/heap limits nor Node Worker `resourceLimits` are configured | Large intermediate sorts or recursive CTEs are bounded only by default process/WASM memory | OPEN | Phase 2 (P0-2) |
| FINDING-005 | Low | `src/index.ts` | `verify_query_safety` response claims native compiled AST evaluation, whereas `node-sql-parser` is a JavaScript PEG parser | Inspecting `verify_query_safety` output shows inaccurate implementation language wording | OPEN | Phase 1 / Phase 2 (P0-6) |
| FINDING-006 | Critical | `src/security/validator.ts` | Derived-table subqueries in `FROM` (`SELECT x FROM (SELECT billing_email AS x FROM customers)`) bypass both table authorization and PII column checks because `item.table` is null on subquery nodes | `SELECT x FROM (SELECT webhook_secret AS x FROM api_keys)` as `analyst` passes `validator.validate()` | OPEN | Phase 2 (P0-5) |
| FINDING-007 | Critical | `src/security/validator.ts` | Common Table Expressions (`WITH` clauses on `ast.with`) are not traversed by the validator | `WITH s AS (SELECT billing_email AS e FROM customers) SELECT e FROM s` as `analyst` passes `validator.validate()` | OPEN | Phase 2 (P0-5) |
| FINDING-008 | Critical | `src/security/validator.ts` | Compound `SELECT` branches (`UNION`, `UNION ALL`, `INTERSECT`, `EXCEPT` chained via `ast._next`) are ignored after the first `SELECT` node | `SELECT id FROM customers UNION SELECT webhook_secret FROM api_keys` as `analyst` passes `validator.validate()` | OPEN | Phase 2 (P0-5) |
| FINDING-009 | Critical | `src/security/validator.ts` | Column checks only inspect direct `col.expr.type === "column_ref"` nodes, allowing PII columns wrapped in functions, casts, binary expressions, or `CASE` expressions | `SELECT LOWER(billing_email) FROM customers` or `SELECT billing_email \|\| '' FROM customers` as `analyst` passes `validator.validate()` | OPEN | Phase 2 (P0-5) |
| FINDING-010 | High | `src/security/validator.ts` | PII columns referenced inside `WHERE`, `GROUP BY`, `HAVING`, or `ORDER BY` are not checked, allowing character-by-character boolean inference | `SELECT id FROM customers WHERE billing_email LIKE 'b%'` as `analyst` leaks PII predicates without returning the column directly | OPEN | Phase 2 (P0-5) |
| FINDING-011 | Medium | `src/security/validator.ts` | Implicit comma joins (`FROM customers a, api_usage b`) and non-equality tautologies (`ON 1`, `ON true`, `ON 1 != 2`) are not rejected by the `CROSS JOIN` check | `SELECT a.id FROM customers a, api_usage b` creates an unconstrained Cartesian product | OPEN | Phase 2 (P0-5) |
| FINDING-012 | Medium | `src/security/validator.ts` | `sqlite_master` and `sqlite_schema` are explicitly permitted for all roles, leaking full `CREATE TABLE` DDL of restricted tables | `SELECT sql FROM sqlite_master` as `analyst` reveals restricted schema definitions | OPEN | Phase 2 (P0-3) |
| FINDING-013 | High | `src/security/rbac.ts` | Missing or invalid credentials silently grant `public_viewer` metadata access instead of failing closed by default | Unauthenticated callers can enumerate non-admin schemas and invoke `verify_query_safety` when no demo flag is set | OPEN | Phase 2 (P0-4) |
| FINDING-014 | Medium | `src/security/validator.ts` | Function filtering uses a denylist containing leftover DuckDB function names rather than an explicit SQLite scalar/aggregate allowlist | Unlisted SQLite functions (`printf`, `zeroblob`, `randomblob`, `sqlite_version`, `likelihood`, unknown UDFs) are permitted by default | OPEN | Phase 2 (P0-3) |
